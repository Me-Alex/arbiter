## Data-truth and functionality upgrade

### Objective translated into verifiable deliverables
“Only real data” will mean the app never presents generated/demo/stale/partial inputs as current actionable betting data. An actionable opportunity must be derived from fresh bookmaker observations, include traceable provenance, use a supported complete market contract, span independent sources, and pass a new verification attempt. Where that proof is unavailable, the UI will explicitly show `empty`, `partial`, `stale`, or `unverified` rather than a fabricated count, a false “confirmed” label, or a guaranteed-profit claim.

This does **not** claim that an upstream bookmaker site or a remote extractor is infallible; it makes the application's data state honest, auditable, and safe by default.

### Current-state audit that drives the work
- `data/latest-scan.json` contains previously started events despite `includePast: false`, sources with widely different capture times, and opportunities formed from one source. Those cannot be treated as live/arbitrage-ready data.
- `src/scanner/engine.mjs` currently accepts any two-or-more selections and does not require separate books or a complete outcome set.
- `src/scrapers/tinyfish-scraper.mjs` currently treats “nothing extracted” as a healthy empty scrape, and can substitute the current time for a missing prematch kickoff.
- `src/verification.mjs` reuses mutable workspace files, so a failed recheck could inherit an old snapshot; it also has a faulty middle-leg condition.
- `/api/scrape/cancel`, the scheduler interval control, and “Save defaults” are currently misleading/no-op behavior.
- `public/preview.html` is publicly served static demonstration data, while the AI page offers an interaction that ends in “not configured.”

## Implementation plan

### 1. Establish a real-data contract and provenance model
**Files:** new `src/shared/data-quality.mjs`; `src/scrapers/base.mjs`; `src/scrapers/tinyfish-scraper.mjs`; `src/scraper-service.mjs`; `src/scrape-orchestrator.mjs`; `src/scanner/scanner.mjs`.

- Generate one orchestrator-owned run ID and pass it through scraping, scanning, verification, reporting, and cataloging.
- Store explicit source metadata with every workspace snapshot: schema version, run ID, source ID, observation/capture time, source URL/run metadata where available, and data health (`fresh`, `empty`, `partial`, `failed`, `stale`, or `cancelled`).
- Separate transport success from usable data. A source with all discovery/extraction attempts failing cannot be reported as a healthy empty result.
- Reject invalid/missing prematch kickoff values instead of inventing `Date.now()` as the event time. Preserve live observations separately with `observedAt`.
- Add configurable freshness limits for prematch and live snapshots. A failed new scrape must not silently reuse an older workspace file as fresh data.

### 2. Make scanner output mathematically and semantically safe
**Files:** new `src/scanner/market-contracts.mjs` (or equivalent); `src/scanner/engine.mjs`; `src/scanner/scanner.mjs`; `src/tinyfish/normalize.mjs`; `src/tinyfish/extract.mjs`.

- Start with a narrow supported market registry for actionable calculations: complete 1X2/match-odds contracts and exact paired over/under line contracts.
- Canonicalize supported outcomes separately from their display labels, including common `1 (Team)`, `X (Draw)`, and `2 (Team)` variations.
- Require every advertised arbitrage to use a complete expected outcome set, valid prices, fresh snapshots, and at least two distinct bookmaker source IDs.
- Keep unknown, boosted, combination, exact-score, special, and partially enumerated markets available in the catalog as informational observations, but never label them as arbitrage or calculate `guaranteedProfit` until a precise payoff model exists.
- Exclude already-started, invalid-date, stale, and no-longer-prematch events from actionable scans regardless of historic/profile options.
- Calculate the post-rounding worst-case payout before exposing profit, and downgrade anything that fails this check.

### 3. Isolate verification and publish only a coherent run
**Files:** `src/verification.mjs`; `src/scrape-orchestrator.mjs`; `src/scanner/scanner.mjs`; `src/scanner/market-catalog.mjs`; `src/state-broadcaster.mjs`.

- Give verification its own pass ID, snapshots, event namespace, and result record instead of reusing and mutating the primary workspace state.
- Require a successful, fresh re-observation for every needed leg in the current verification pass. Missing, failed, empty, stale, or invalid legs become `unverified`/`expired`, never confirmed.
- Fix the middle verification leg-count bug and apply the same supported-market contract checks to verification.
- Prevent transient manual/verification scans from replacing canonical `latest-scan.json`; publish only after the complete scrape → scan → verify → catalog lifecycle finalizes.
- Emit precise phase/run events so the UI state, scrape report, and persisted state cannot overwrite each other or disagree.

### 4. Make the operational controls real
**Files:** `src/scrape-orchestrator.mjs`; `src/scraper-service.mjs`; `src/verification.mjs`; `src/tinyfish/{client,discovery,extract}.mjs`; `src/shared/lock.mjs`; `src/scheduler-service.mjs`; `src/router.mjs`; `src/server.mjs`; relevant page scripts.

- Implement a run-owned `AbortController`, real cancellation endpoint, `cancelling`/`cancelled` terminal state, lock release in `finally`, and signal propagation to queued/running scraper and TinyFish work.
- Replace the fragile elapsed-time lock behavior with exclusive acquisition, ownership validation, and a heartbeat/lease policy so long real scrapes cannot overlap.
- Make the scheduler honor, persist, validate, and report the selected interval, books, and scan settings. On restart, its status will truthfully indicate whether it resumed or is paused rather than claiming an inactive timer is enabled.
- Change passive scanner-page refreshes to read the canonical scan with `GET`; only explicit user rescan actions may create non-publishing preview/manual results.
- Replace “Save defaults (in-memory only)” with a persisted local preference endpoint, or remove the control if no durable preference is warranted.

### 5. Remove all production synthetic/misleading presentation
**Files:** `public/preview.html`, `public/css/preview.css`, `public/js/pages/preview.js`; `public/{index.html,admin/*.html}`; `public/js/pages/{dashboard,scrape,scanner,analytics,ai,login}.js`; server static routing; README.

- Remove the hard-coded visual preview from the production-served `public/` tree (or block it server-side); keep any design artifact outside the served app and explicitly marked synthetic.
- Replace static “Live odds”/“syncing” language with actual source health, observation timestamps, run ID, freshness, and verification status returned by the API.
- Turn the nonfunctional AI prompt into an honest deterministic “Scan Insights” panel backed only by the current real scan, or remove the prompt/action when no AI service is configured. It will not pretend to answer questions.
- Remove the fake login/password claim (which currently accepts any non-empty string) rather than presenting it as authentication. The local-only access model will be accurately described unless a real server-side authentication flow is added later.
- Ensure every empty state communicates whether there were truly zero fresh observations, a partial run, a stale run, or no successful source data.

### 6. Tests and proof gates
**New/extended tests:** scanner, engine, TinyFish normalization/extraction, scraper service, verification, orchestrator, scheduler, lock, router, SSE, frontend policy tests.

Required cases include:
- A one-book or incomplete/special market cannot create arbitrage.
- A valid cross-book supported market can create an opportunity only when all legs are fresh.
- A past, invalid, missing, or stale kickoff/snapshot cannot become actionable.
- All extraction failures are `failed`/`partial`, never healthy-empty.
- Failed verification cannot use old workspace data to confirm a price.
- Verification job events cannot corrupt primary scrape state.
- Cancellation stops queued work, produces `cancelled`, prevents publication, and releases the lock.
- Scheduler settings round-trip and report an accurate active/paused state after restart.
- No normal production page contains demo match/odds/tracker data, preview assets, no-op control text, or fake AI output.
- API responses expose one coherent run ID and source-quality summary.

### Completion audit checklist
| User requirement | Evidence to collect before declaring work complete |
| --- | --- |
| Upgrade functionality | Real cancellation, durable settings/scheduler behavior, coherent state/SSE lifecycle, non-publishing manual scans, and no misleading controls, covered by focused tests. |
| Only real data | No served demo preview; source/run provenance persisted; freshness gate; strict supported-market contracts; cross-book requirement; verification based on fresh pass snapshots; truthful UI health states. |
| No false actionability | Tests proving same-source, incomplete, stale, past, failed, and unverified inputs cannot expose guaranteed profit or confirmation. |
| Regression safety | `npm run lint`, full `npm test`, static served-page audit, local HTTP smoke test, and—only when configured/authorized—TinyFish diagnosis plus bounded live smoke against an actual bookmaker. |

### Delivery sequencing
I will implement this in small test-backed increments: data-quality and safe scanner gating first, then isolated verification and true controls, then the truthful UI cleanup. That sequencing intentionally reduces the apparent opportunity count before it adds richer functionality, because rejecting misleading signals is necessary to meet the real-data requirement.
